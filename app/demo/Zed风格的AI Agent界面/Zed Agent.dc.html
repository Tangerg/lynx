思考过程 6.2s · 812 tokens

当前 handler 用 await res.json() 一次性取回，所以首字节要等整段生成完。改 SSE 的关键不是写 header，而是把上游 fetch 的 body 直接透传，避免中间再做一次完整缓冲。

Edge Runtime 下 ReadableStream 的背压由 controller 的 desiredSize 决定。如果用 start() 里 while 循环 enqueue，就绕过了背压；应该用 pull()，让消费端拉取速度反向控制上游读取。

还要确认客户端断开时 abort signal 有没有传到上游，否则并发下会泄漏连接。先读代码确认，再动手。

现状与结论

当前 handler 在 route.ts:46 把整个上游响应 buffer 完才返回，所以首字节延迟等于整段生成时间。lib/stream.ts 里已经有一个没被用上的 toSSE()，直接复用即可。

  • 上游请求改为 stream: true，直接透传 body，不做二次缓冲。
  • 用 pull() 而非 start() 里的 while 循环，让背压生效。
  • 把 req.signal 传给上游 fetch，客户端断开时同步取消。
注意：Edge Runtime 不支持 node:stream。如果之后要跑在 Node runtime，需要另写一层适配，参考 Edge 运行时说明。
